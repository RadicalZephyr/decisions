# Notes

Where a thought landed before there is evidence for it: an idea, what a
conversation settled, what it would take to find out. Nothing here is
authoritative, and nothing here is a commitment.

A note is a way into a decision, not the start of one. Most never reach a
record, and that is fine -- unlike an experiment, a note has a valid resting
state. [`../README.md`](../README.md#before-a-record-notes-and-research) has the
path from here to research and to a record.

## Files

One note per file, `YYYY-MM-DD-kebab-case-title.md`, dated the day it was
started, so the directory lists in the order the thoughts arrived.

A note opens with one italic line giving its date and how much of it has run --
nothing, part of it, or all of it:

```markdown
_2026-10-05. An idea: nothing here has been tried._
```

That line does for a note what the summary line does for a record: a reader
knows at a glance whether they are reading an idea or evidence. A note that has
partly run says which part, and where.

## Kept as written

A note is edited freely until it merges to the default branch. After that it is
kept as written: later information is a new note, or a dated addition at the
end, under a heading that says when it arrived.

```markdown
## Addendum, 2026-10-12: the second run
```

At the end, not beside the reasoning it concerns, which is where a record puts
one. A record is a projection, kept current. A note is a snapshot of where a
thought landed on its date, and appending keeps the snapshot whole.

The gate is the merge because a note has nothing else to use. A record ends its
drafting at a status row, and a note has none.

Research notes are kept the same way, by this rule.
